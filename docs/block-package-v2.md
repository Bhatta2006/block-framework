# Block package format v2

Phase 0 migrates `content.hero`, `data.collection`, and `auth.account`; semantic references stay `@1.0.0`. The other sixteen contracts and native renderers remain supported. `block.json` extends the exact existing `manifest.json` contract; registration rejects disagreement, so there are no independently editable config/event schemas.

The manifest schema is `packages/manifest/src/schema/block-package-v2.json`. Required additions are formatVersion 2, targets, license, stability, requires (services/entities/blocks/env names), provides (entities/routes/flowSteps/events/slots), typed slot categories, bindings, designTokens, permissions, pinned dependencies, implementations and files. Empty capability arrays are deliberate: declaring future full-stack support does not implement it. Existing environment credentials stay in server configuration, never block config.

Each file declares a package-relative source path, an export-relative `src/` target and supported platforms. Entries identify an exported component. Only native targets may explicitly retain the existing `legacy-template` adapter. Hero and Collection declare web/ios/android; Account declares web only. Paper Cloud native still rejects before export.

The real web implementations are Hero.tsx, DataCollection.tsx and CloudRuntime.tsx. Collection's portable record store is shared/data-core.ts. The Collection file also retains the shared provider/editor/summary to avoid splitting persistent-store ownership. Account retains the existing real Supabase runtime and its error/session/owner protection. Web exports vendor these modules; native Collection uses the same real portable store plus its existing renderer. Source is typechecked and linted in the framework; three component render tests cover events, store selection and auth-provider requirements.

The compiler assembles `src/blocks/composition.tsx` with ts-morph structures and formats it using pinned Prettier in a synckit worker. Config remains typed props. Existing web design decoration remains the supported style/event layer; native JSX customization is retained until all native blocks migrate. The preview copies every compiled source module, so previews and independent exports execute the same vendored code.

Registration rejects missing files, traversal, symlink escapes, duplicate destinations, undeclared target implementations and disallowed licenses. Vendoring checks relative/static imports and pinned external dependencies, and rejects dynamic imports/re-exports. `blockRegistryItem()` produces the shadcn registry:block shape with content/files/dependencies and the complete contract in `meta.block`; this does not publish a registry.

`LicenseRef-Project` records that the three sources are this repository's existing authored code. This repository has no LICENSE file; migration does not invent an open-source grant. The third-party allowlist is enforced for incoming sources. A public marketplace release still needs an explicit project licensing decision and bundled notices. No external component code was copied in this step. React is a peer dependency to preserve a single hook dispatcher in authoring/tests; generated apps retain their existing pinned React dependencies.

`blockfw.lock.json` records schema/IR versions, exact type references, canonical manifest SHA-256 and normalized source SHA-256. Web locks also pin the two shared reference modules always included in the existing runtime, plus Account for cloud. Existing legacy contracts are pinned by manifest digest; vendored v2 source is additionally pinned by file digest. No timestamp, path to Studio, secret or runtime @blockfw dependency appears in exports.

Storybook and the new Radix/Tailwind/NativeWind UI stacks are not installed in Phase 0. These reference files preserve the current application CSS and semantics, as recorded in ADR-0002. Framework render tests and the isolated Puck evaluation exercise them now; Storybook infrastructure and visual replacement belong to the later component-library work.
